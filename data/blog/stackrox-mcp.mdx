One of the questions I get asked frequently is - "How do I actually integrate AI into my security workflows?" Not in the abstract, 'hand-wavy' sense, but *practically* - how do you connect an AI assistant to the tools and platforms you're already using?

This is the problem that the [StackRox MCP server](https://github.com/stackrox/stackrox-mcp) solves. It's a Model Context Protocol (MCP) server that connects AI assistants directly to [StackRox](https://github.com/stackrox/stackrox), the upstream project for Red Hat Advanced Cluster Security for Kubernetes (RHACS). Instead of copy-pasting CVE lists or manually querying the RHACS API, you can ask an AI assistant to do it for you - in natural language.

I think AI model harnesses are worth a closer look before we dive into the internals of the StackRox MCP server.

## AI model harnesses

The Australian Signals Directorate (ASD) recently published a great article on [frontier AI models and their impact on cyber security](https://www.cyber.gov.au/about-us/view-all-content/news/frontier-ai-models-and-their-impact-on-cyber-security-an-update-on-ai-model-harnesses). One of the key concepts introduced is the idea of an **AI model harness** - the orchestration layer built around one or more AI models that includes planning, tool use, output verification, and multi-agent coordination.

ASD uses the term "harness" rather than "agent framework" deliberately. It emphasises that it's the *engineered system*, not the model alone, that delivers capability. I think this is an important distinction.

The really interesting finding from ASD's research is this: **a well-engineered harness can be as important a determinant of capability as the underlying AI model itself.** A capable harness orchestrating mid-tier AI models can achieve results comparable to those of top-tier frontier models. You don't need the biggest, most expensive model to get meaningful outcomes - you need good engineering around whatever model you're using.

The ASD article also highlights several examples of AI harnesses applied to cyber security:

- **Microsoft's MDASH**: A multi-model harness orchestrating over 100 specialised AI agents. Microsoft credits MDASH with helping identify vulnerabilities across Windows networking and authentication components, contributing to their June 2026 Patch Tuesday release of 206 vulnerability patches - their largest on record.
- **Anthropic's Defending Code Reference Harness**: An open-source reference implementation for autonomous vulnerability discovery and remediation.
- **OpenHack**: An MIT-licensed open-source project from security firm Hadrian that packages automated vulnerability research workflows.

What all of these have in common is that they connect AI models to *tools*. The model reasons about the problem, while the harness gives it the ability to take action - querying APIs, running scans, analysing results, and feeding those results back into the next step.

This is where the Model Context Protocol (MCP) comes in.

## What is an MCP server?

MCP is an open protocol that standardises how AI assistants connect to external tools and data sources. Think of it as a universal adapter between AI models and the systems they need to interact with.

An MCP server exposes a set of tools that an AI assistant can discover and use. Each tool has a name, a description, and a schema that defines its inputs and outputs. The AI assistant reads these descriptions, figures out which tool to use for a given task, and calls it with the right parameters.

This is exactly the "tool use" component that ASD describes in the AI harness model. An MCP server provides the structured, standardised interface that allows an AI model to move beyond just generating text and into actually querying systems, retrieving data, and taking action.

The beauty of the MCP approach is that it's model-agnostic. The same MCP server works whether you're using Claude, GPT, or any other model that supports the protocol. The harness engineering - the tools, the data access, the domain knowledge - lives in the server, not in the model.

## The StackRox MCP server

The [StackRox MCP server](https://github.com/stackrox/stackrox-mcp) connects AI assistants to StackRox Central, giving them the ability to query your Kubernetes security posture in natural language. It's currently in Developer Preview, and supports two main toolsets:

- **Vulnerability management**: Query for CVEs, GitHub Security Advisories (GHSAs), and Red Hat Security Advisories (RHSAs) across clusters, namespaces, deployments, and nodes.
- **Configuration management**: Query and manage StackRox Central configuration.

The server supports two transport modes - streamable HTTP (for running as a service) and stdio (for direct CLI integration). It can be deployed as a local binary, a container image, or via a Helm chart into Kubernetes or OpenShift.

By default, the server runs in read-only mode, which is a sensible starting point. You can query your security posture without worrying about accidentally modifying anything.

## Testing out the StackRox MCP server

Great! The MCP server is running. Let's check it's working correctly before integrating with Claude.

The MCP server uses Server Sent Events (SSE), so you will need to maintain a session across commands (Claude will do this for you):

```json
SESSION=$(curl -si --max-time 2 http://localhost:8080/mcp \
    -H "Content-Type: application/json" \
    -d '{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":"2025-03-26","clientInfo":{"name":"curl","version":"1.0"},"capabilities":{}}}' \
    2>/dev/null | grep -i 'mcp-session-id' | tr -d '\r' | awk '{print $2}')
```

This command will list the available tools:
```json
curl -s http://localhost:8080/mcp \
    -H "Content-Type: application/json" \
```

## Claude integration
Integrating the StackRox MCP server with Claude is straight-forward. I'm going to use `claude mcp` to add the MCP server (note that for testing I am simply using static authentication again):
```json

}
```

## Violations and alerts

One of the capabilities I've been working on is support for querying policy violations (alerts) from StackRox. I recently submitted a [pull request](https://github.com/stackrox/stackrox-mcp/pull/153) that adds a `list_violations` tool to the MCP server, allowing AI assistants to retrieve policy violation alerts with filtering by cluster, namespace, policy, severity, and state.

This means you can ask an AI assistant questions like "show me all critical severity violations in the production namespace" or "what policy violations have been triggered in the last 24 hours", and it will query StackRox directly and return the results.

### Trying out the new alerts support
As at the time of writing the PR I created is currently in-review, but here's a look at how it can be used.

Firstly, grab my PR and map it to a local branch:
```
$ gh pr checkout 153 --repo stackrox/stackrox-mcp --branch your-local-branch-name
```
Rebuild your binary:
```
$ make build
```
Update your configuration to enable the new `violations` tool:
```yaml
# Configuration of MCP tools
# Each tool has an enable/disable flag. At least one tool has to be enabled.
tools:
  # Vulnerability management tools
  vulnerability:
    # Enable vulnerability management tools (optional, default: false)
    enabled: true

  # Configuration management tools
  config_manager:
    # Enable configuration management tools (optional, default: false)
    enabled: true

  # Violations management tools
  violations:
    enabled: true
```

### Why this matters

Coming back to the ASD harness model - the StackRox MCP server is exactly the kind of tooling that makes AI harnesses practical for Kubernetes security. It provides the structured interface that allows an AI assistant to:

1. **Discover** what security tools are available (MCP tool discovery)
2. **Query** the current security posture (vulnerability and violation data)
3. **Reason** about the results (the AI model's job)
4. **Act** on the findings (with appropriate safeguards like read-only mode)

This is the loop that ASD describes. The model provides the reasoning; the harness provides the tools and the guardrails. And MCP provides the standard interface that connects the two.

## Wrapping up

The StackRox MCP server is a great example of what ASD calls 'AI harness engineering' applied to Kubernetes security. It takes the security data that StackRox already collects - vulnerabilities, policy violations, cluster configurations - and makes it accessible to AI assistants through a standardised protocol.

The key insight from ASD's research is worth repeating: you don't need the most powerful AI model to get meaningful security outcomes. You need good engineering around the model - the tools, the data access, the guardrails. The StackRox MCP server provides exactly that for Kubernetes security.

If you're interested in contributing, the project is open source and available on [GitHub](https://github.com/stackrox/stackrox-mcp). And if you want to see the violations support in action, keep an eye on [PR #153](https://github.com/stackrox/stackrox-mcp/pull/153).
